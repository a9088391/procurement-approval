# 前端開發與身分恢復

登入、身分、改密碼、登出、組織管理、有限改派、本人請購草稿及請購查閱與簽核都使用同一頁面。React 處理畫面與表單，`src/api.ts` 集中明確 DTO 與 HTTP 邊界。後端負責授權、輸入驗證、登入及金額的權威判斷，前端驗證用於協助填寫。

## 程式入口

- `frontend/index.html`／`src/main.tsx`：React 掛載、可存取表單與身分生命週期。
- `frontend/src/api.ts`：請求／回應 DTO、同源 HTTP、防偽 token 與錯誤。
- `frontend/src/Organization.tsx` 管理組織快照、提交、讀回與錯誤恢復。
- `frontend/src/OrganizationForms.tsx` 管理部門、業務帳號及密碼重設表單，使用 `api.ts` 定義的欄位。
- `frontend/src/Reassignments.tsx` 管理有限待辦、指定關卡及人選、原因驗證與改派結果讀回。
- `frontend/src/RequisitionDrafts.tsx` 管理本人可編輯的請購、版本、保存、刪除草稿與讀回。
- `frontend/src/RequisitionApprovals.tsx` 管理授權清單、各輪快照、送審、撤回、審核及結果讀回。
- `frontend/src/RequisitionDraftForm.tsx` 保留明細輸入原字串，驗證可編輯欄位及呈現金額預估。
- `frontend/src/style.css`：單欄版面、手機排版與鍵盤焦點。
- `frontend/e2e/auth.spec.ts`：真 API 成功／錯誤流程及標示 mocked 的 UI 恢復案例。
- `Dockerfile`：固定 Node 建置靜態檔，再複製至 ASP.NET Core `/app/wwwroot`；正式環境只有一個網站來源。

每次載入先從 `/api/auth/csrf` 取得防偽權杖，再讀取目前身分。確認為匿名時，登入表單使用前一步取得的權杖。已登入時，以同一個 `/api/auth/me` 回應的 JSON 與 `X-CSRF-TOKEN` 標頭建立畫面身分，避免在分頁換帳號時採用其他請求取得的權杖。成功身分回應缺少權杖時進入身分恢復。登入、登出與改密碼後都重新查證身分。Cookie 由瀏覽器管理，前端只在記憶體保留權杖。

寫入期間停用表單及其他操作，另以同步 guard 擋住重複事件。登入、登出和改密碼的表單依身分狀態掛載。這些操作遇到過期版本、安全權杖失效或結果未知時，可手動確認身分。操作收到 `401 unauthenticated` 時會先嘗試重讀身分，讀取失敗時保留手動恢復入口。

身分操作遇到網路或 500 錯誤時，交易可能已提交。「重新確認身分」只執行 GET。原本的未知結果提示會保留至成功登入或成功變更密碼。若改密碼可能已生效，使用者可先嘗試新密碼。成功回應後若無法讀取身分，畫面會分別提示操作已成功及身分尚待確認。

管理員完成身分驗證後才會載入組織設定。業務帳號若需要先改密碼，會在既有改密碼表單看到提示。管理畫面的部門和帳號設定使用讀取時的版本，保存成功後重新查詢；預設人選及部門選單可辨識已保存但不再符合資格的設定。

組織管理與身分操作共用送出閘門。臨時密碼在提交時從表單清除。一般驗證錯誤保留其他欄位供修正。版本過期、目標失效或寫入結果未確認時，先按「重新讀取組織設定」比對最新值，重新讀取只執行 GET。若已收到成功回應但讀回失敗，畫面仍會告知保存已完成。切換至有限改派再返回時，同一管理帳號會保留這項確認，可手動讀回目前設定。先前未決的警示與本次操作的結果分開顯示。登入、管理資格或安全權杖失效時，管理資料會卸載，可按「重新確認身分」恢復。

## 有限改派

完成身分驗證的管理員可從管理功能選擇「有限改派」。清單獨立載入，僅顯示單號、送審部門、目前關卡、暫停提示與人選。表單只開放未完成的關卡，將版本、目標關卡、接手人及交接原因送給後端重新驗證。業務帳號的操作歷程依原有查閱範圍顯示改派前後人選、原因、操作者與時間。

管理待辦的 GET 與 POST 使用已驗證管理身分的配對權杖，並和身分操作共用送出閘門。確認改派成功後讀取目前待辦。遇到版本衝突、讀回失敗或結果未確認時，按「重新讀取結果」只執行 GET。可比對目前指派或確認該單已離開待辦，但目前指派無法單獨證明一次未確認的請求已提交。帳號或權杖暫時失效時卸載受保護資料，重新確認為同一管理帳號後可繼續讀回。確認登出、確認切換帳號或整頁重載會清除待核對標記。

## 本人草稿

本人草稿在確認業務身分及解除改密碼限制後掛載，與身分操作共用送出閘門。畫面將數量與單價保留為輸入文字，驗證格式後才組成請求 DTO，方便使用者修正超精度輸入。TWD 預估在畫面以整數分計算，保存時使用 API 回傳的金額與版本。欄位尚未齊全時，畫面將可計算小計標示為部分金額。草稿與撤回修改中的請購都可從本人清單重開。刪除按鈕只出現在從未送審的草稿。

保存或刪除送回讀取時的版本。版本衝突或寫入結果未知時保留目前輸入，依畫面指示讀回草稿明細或清單，再決定下一步。未保存的內容只留在編輯畫面記憶體。草稿的清單及明細 GET 帶上畫面已確認身分的防偽權杖。若其他分頁更換共用的登入 Cookie，權杖失配會讓舊分頁卸載草稿資料。登入或權杖失效後，使用者須先重新確認身分，再載入目前帳號可見的草稿。

## 請購查閱與簽核

業務帳號先使用草稿畫面保存內容，再切換到「請購查閱與簽核」，透過單號開啟明細。面板切換沿用草稿離開確認。清單與明細都帶著與畫面身分成對的權杖。動作按鈕依後端回應的 `canSubmit`、`canWithdraw` 與 `canDecide` 顯示。案件暫停時保留原關卡，仍以伺服器回傳的撤回資格為準。本人可讀取各輪快照，畫面將撤回後的可編輯內容與舊輪快照分開呈現。

送審、撤回、核准與駁回共用應用程式的操作閘門。寫入只傳讀取時的版本。收到過期版本、資格改變或結果未確認的提示時，用「重新讀取結果」核對目前明細及歷程。系統只執行 GET，後續動作由使用者依讀回結果決定。尚待核對的寫入與已確認成功但尚待取得新版明細的寫入，都會在頁面記憶體依帳號和請購識別保存提示。明細讀取與寫入回應都會確認請購識別與所需欄位，驗證失敗時保留讀回入口。部門名稱依伺服器提供的文字原樣呈現。請購讀寫遇到登入、權杖或身分資格拒絕時，會卸載受保護畫面，再由使用者確認身分。

若撤回使審核者讀不到原單，或重送後只能看新一輪，畫面會說明先前結果無法從目前可見資料確認，並結束該筆重讀。可查閱的新輪次仍依伺服器回傳的資格提供操作。

## 固定工具鏈與命令

Node `24.22.2`、React／React DOM `19.3.1`、TypeScript `7.0.2`、Vite `8.3.5`、Prettier `3.9.10`、Playwright `1.64.1`；型別套件與全部相依固定於 `package.json`／`package-lock.json`。只依賴 React 與 React DOM 作為 production dependencies。不需要額外 React plugin 即可編譯此 TSX；目前未設定 Fast Refresh。

在根目錄使用 Linux 容器還原及檢查，避免將 macOS native 套件混入 Linux 建置：

```sh
docker compose -p procurement-approval-browser -f compose.yaml -f compose.browser.yaml run --rm --no-deps frontend-tools npm ci
docker compose -p procurement-approval-browser -f compose.yaml -f compose.browser.yaml run --rm --no-deps frontend-tools npm run build
docker compose -p procurement-approval-browser -f compose.yaml -f compose.browser.yaml run --rm --no-deps frontend-tools npm run format:check
```

`build` 包含 `tsc --noEmit`，啟用 strict、noUnusedLocals 及 noUnusedParameters，型別檢查也包含瀏覽器測試。格式命令採 check-only，不會改檔。

需要本機 Vite 開發時，使用符合固定版本的 Node，在 `frontend/` 執行 `npm ci`、`npm run dev`；勿與容器共用跨平台的 `node_modules`。先啟動 `5080` 後端，瀏覽器只開啟 Vite 輸出的 `127.0.0.1:5173`。Vite 將相對 `/api` 代理至 `127.0.0.1:5080`，避免在兩個來源交替操作同一個登入流程。正式驗收使用同源 Compose 網站。
